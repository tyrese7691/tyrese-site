CaliSpot: supporting a live app's users

CaliSpot helps people find outdoor calisthenics spots and events. It's live on iOS and Android. I've handled every question, bug report and feature request since launch.

3,000+iOS downloads
2,300+signups
270weekly active users
+20%weekly active users in 2 months
The challenge
Handling every user question, bug report and feature request across two platforms on my own.
What I did
Gathered messages from in-app feedback, email, Instagram and app store reviews. I replied personally, reproduced each problem, then fixed it, found a workaround or logged it for the next release.
Closing the loop
Grouped recurring complaints and requests, turned the most common into prioritised fixes, and told users when something they reported had shipped.
The result
Weekly active users grew 20% over two months as fixes and requested features shipped. I also brought on an equipment-brand partner and looked after the relationship end to end.
What I'd do differently
Set up a help centre and saved replies earlier, so common questions answer themselves and more time goes on the problems that need a person.

Two decisions from user feedback

Search bar before dark mode

One person asked for dark mode. Meanwhile, finding a park meant scrolling around the map, which affected everyone.

So I built a map search bar first. Users responded well to it.

What people actually use the app for

In one month there were 4,669 app opens but only 60 logged workouts.

People come back to find places to train, not to log training. That changed what I built next.
